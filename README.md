文件中转站悬浮应用 PRD 文档
文档基础信息
文档名称：跨局域网本地文件中转站悬浮工具 PRD
适用终端：HarmonyOS 手机 / 平板、Ubuntu PC
核心定位：同局域网无公网本地文件流转悬浮工具，两端共享文件池，支持拖拽存入、媒体预览、批量管理
优先级划分：P0 核心能力、P1 体验优化、P2 迭代拓展
开发约束：HarmonyOS 使用 ArkTS/ArkUI；Ubuntu PC 使用 Qt6 (QML/C++)，两端无法统一 ArkTS，底层通信 SDK 复用
一、需求描述
1.1 业务目标
提供桌面常驻悬浮窗形态文件中转站，无需打开完整应用即可快速存取文件；
同一局域网可信设备共享统一文件池，文件仅内网 TCP/UDP 传输，不上传公网；
优先打通 HarmonyOS 移动端 ↔ Ubuntu PC 双向文件同步、拖拽互传；
支持图片、视频内置预览播放，文档 / 压缩包基础展示；
提供文件批量多选、删除、设备可信授权、悬浮窗基础配置能力。
1.2 用户角色
表格
用户角色	使用设备	核心诉求
移动办公用户	HarmonyOS 手机	手机文件快速传到电脑，电脑文件下发至手机，桌面悬浮快捷操作
开发 / 设计办公用户	Ubuntu PC	电脑本地文件拖拽至中转站，同步至手机，悬浮窗常驻不遮挡工作窗口
1.3 P0 核心需求（必须一期完成）
1.3.1 悬浮窗口基础形态与状态切换
悬浮窗默认停靠屏幕右侧偏上，圆角矩形面板，分堆叠收缩态、完全展开态两种模式；
收缩态：窄条状悬浮卡片，顶部文字「中转站」，右上角展示站内文件数量红色角标；
触发展开条件：点击收缩悬浮条、系统检测全局文件拖拽动作时自动展开；
展开态规则：
宽度固定，高度自适应文件条目，设置全局最大高度阈值；
文件高度未达阈值：首次点击自适应高度，再次点击拉满最大高度；
文件高度超出阈值：固定最大高度，列表支持垂直滚动；
自动回收规则：展开状态无操作停留 5s，自动切回收缩态；点击悬浮窗外部区域，立即收缩。
悬浮窗顶部右上角四点「⋮」操作按钮，点击弹出下拉菜单：多选、设置、关闭。
1.3.2 文件基础操作与媒体预览
文件存入方式：拖拽全局文件至悬浮展开面板、面板内点击添加文件；
文件列表纵向自上而下堆叠展示，单条目包含：文件缩略图、文件名、文件大小 / 视频时长；
媒体内置预览：图片点击弹窗原图查看，视频点击悬浮窗内嵌播放器直接播放；
关闭预览面板后返回文件列表。
1.3.3 局域网本地文件共享（无公网）
参考 LocalSend 技术逻辑，基于 UDP 组播设备发现 + TCP 点对点内网传输；
同一 Wi-Fi 局域网内可信授权设备共用一套中转站文件池；
HarmonyOS ↔ Ubuntu 双向实时同步文件：一端新增 / 删除文件，所有可信设备同步变更；
文件传输全程内网流转，不经过互联网服务器，传输流 AES 加密；
设备配对授权：首次接入需扫码确认，加入可信设备白名单，断网重连自动同步。
1.3.4 基础文件管理
四点菜单选择「多选」，进入批量勾选模式；
勾选多个文件后，面板底部出现批量删除按钮，一键清理选中文件。
1.4 P1 体验优化需求（二期迭代）
设置页面能力：悬浮窗位置锁定、自动收起时长调整、文件本地缓存过期自动清理、传输限速；
传输优化：文件 MD5 哈希秒传、大文件分片、断点续传；
设备管理页：查看当前在线可信设备、移除不信任设备、手动输入 IP 连接设备（UDP 广播屏蔽降级方案）。
1.5 P2 拓展需求（三期迭代）
拓展 Windows /macOS PC 客户端适配；
传输日志记录、同步记录审计；
文件拖拽分享至第三方应用；
中转站文件夹分类管理。
1.6 非需求范围
跨路由器 / 跨网段设备互通；
公网远程传输、云存储中转；
第三方账号登录、云端文件备份；
复杂文档在线编辑，仅提供基础预览。
二、交互原型说明（结合鸿蒙参考截图）
2.1 全局悬浮窗交互规范
2.1.1 状态 1：堆叠收缩态（初始默认，对应第一张截图）
UI 布局：窄圆角矩形悬浮条，居屏幕右侧偏上；
内容：左侧文字「中转站」，右上角红色圆形角标展示文件总数（例：3）；
交互：
单击悬浮条 → 切换完全展开态；
全局拖拽文件时，系统监听拖拽事件，自动切换展开态，支持拖入文件；
窗口置顶，不被普通应用窗口遮挡。
2.1.2 状态 2：完全展开态（对应第二张截图）
UI 布局：固定宽度圆角侧边面板，纵向排列文件条目；
顶部标题栏：左侧「中转站」文字，右上角四点⋮操作按钮；
文件列表：自上而下纵向堆叠，超出最大高度支持垂直滚动；
自动收缩：无任何点击 / 拖拽操作 5 秒倒计时结束，自动切收缩态；
外部点击：点击桌面 / 应用其他区域，立即切回收缩态。
2.1.3 四点下拉菜单交互（对应第四张截图）
点击右上角⋮，弹出浮层下拉菜单，自上而下三个选项：多选、设置、关闭
多选：进入批量选择模式，文件条目出现勾选框；
设置：跳转中转站配置页面；
关闭：仅收起悬浮窗至收缩态，后台同步服务持续运行，不退出程序。
2.2 文件操作交互流程
2.2.1 文件存入流程
流程 1（拖拽存入）：
用户长按拖动本地图片 / 视频 / 文档；
系统触发全局拖拽监听，悬浮窗自动展开；
拖拽文件移入悬浮面板区域，松开鼠标 / 手指；
文件存入本地中转站，内网同步至所有可信设备，列表实时刷新。
流程 2（手动添加）：
悬浮窗展开状态下，点击列表底部「添加文件」按钮；
唤起系统文件选择器，选中文件确认；
文件存入并同步局域网设备。
2.2.2 媒体预览交互
图片文件：点击列表图片条目，弹出悬浮大图预览面板，单击面板任意位置关闭预览；
视频文件：点击视频条目，面板内嵌播放器自动播放，支持暂停、进度拖动，点击关闭按钮退出播放。
2.2.3 批量删除交互
点击右上角四点 → 选择「多选」；
点击多个文件条目勾选，底部出现红色「批量删除」按钮；
点击批量删除，弹窗二次确认；确认后本地删除文件，同步删除所有局域网设备中转站对应文件；
点击空白区域退出多选模式。
2.3 跨设备同步交互流程
Ubuntu PC / HarmonyOS 手机连接同一 Wi-Fi 局域网；
应用后台 UDP 广播扫描网段内在线中转站设备；
新设备弹窗配对二维码，已授权设备扫码确认，加入可信设备列表；
配对完成后两端文件池实时双向同步：一端新增 / 删除，另一端列表自动刷新；
设备断开 Wi-Fi：本地缓存保留文件，重连局域网自动同步两端文件差异。
2.4 窗口尺寸切换交互
文件总高度 < 最大高度阈值：首次点击收缩条展开为自适应高度；再次点击悬浮面板，拉伸至最大限定高度；
文件总高度 > 最大高度阈值：点击直接展开至最大高度，列表支持上下滚动浏览全部文件。
三、接口协议（局域网跨端通信协议，兼容 HarmonyOS + Ubuntu）
3.1 基础通信规范
设备发现：IPv4 UDP 组播地址 224.0.0.1，端口 53317；
文件传输：TCP 点对点连接，端口 53318；
数据格式：统一 JSON 报文，传输二进制文件时采用分片二进制流 + JSON 包头；
安全机制：设备配对使用 RSA 交换密钥，文件传输二进制流 AES-128 加密；
协议参考：基于 LocalSend 开源通信协议精简改造。
3.2 UDP 设备发现报文（广播）
发送报文（设备广播自身信息）
json
{
  "msgType": "deviceAnnounce",
  "deviceId": "设备唯一UUID",
  "deviceType": "harmonyos/ubuntu",
  "deviceName": "办公手机/开发PC",
  "version": "1.0.0",
  "publicKey": "设备RSA公钥"
}
响应报文（收到广播设备回包确认）
json
{
  "msgType": "deviceAck",
  "targetDeviceId": "广播设备ID",
  "isTrusted": true/false
}
3.3 TCP 文件同步核心指令
指令 1：文件新增同步
json
{
  "cmd": "fileAdd",
  "fileId": "文件唯一MD5",
  "fileName": "demo.mp4",
  "fileType": "image/video/doc",
  "fileSize": 1048576,
  "fileDuration": 33, // 视频专用，图片/文档为0
  "createTime": "2026-08-08 11:53:00",
  "chunkTotal": 4 // 文件总分片数
}
后续跟随二进制分片文件流，每分片 4MB。
指令 2：文件删除同步
json
{
  "cmd": "fileDelete",
  "fileId": "文件唯一MD5"
}
指令 3：全量文件池同步（设备重连时触发）
json
{
  "cmd": "syncAllFiles",
  "fileList": [
    {
      "fileId": "xxx",
      "fileName": "xxx.jpg",
      "fileSize": 1024
    }
  ]
}
3.4 设备配对授权协议
新设备发送配对申请 cmd: pairRequest，携带设备公钥；
已授权设备弹窗展示二维码（编码设备 ID + 公钥）；
扫码确认后，返回 pairAccept，交换 AES 会话密钥；
设备 ID 持久化存入本地可信设备白名单。
3.5 本地数据库存储接口（两端通用数据结构）
使用 SQLite 存储本地文件元数据、可信设备列表
文件元数据表：file_info
表格
字段	说明
file_id	文件 MD5 唯一标识，主键
file_name	文件名称
file_type	文件类型 image/video/doc
file_size	文件字节大小
duration	视频时长，非视频为 0
cache_path	本地缓存路径
create_time	文件存入时间
expire_time	文件自动过期清理时间
可信设备表：trusted_device
表格
字段	说明
device_id	设备 UUID 主键
device_name	设备名称
device_type	harmonyos/ubuntu
public_key	设备 RSA 公钥
last_online	最后在线时间

4.2 HarmonyOS 移动端细分架构
UI 层：ArkTS + ArkUI
WindowStage 侧边悬浮窗口管理；
ArkUI 声明式页面：收缩条、展开文件列表、多选弹窗、设置页；

NAPI 桥接层：C++ 编写原生 NAPI 接口，调用通用 SDK 能力；
通用 SDK 层：复用统一通信、加密、文件管理逻辑。
系统能力依赖：悬浮窗权限、文件读写权限、局域网网络权限。
4.3 Ubuntu PC 端细分架构
UI 层：Qt6 QML + C++
QML 实现右侧圆角悬浮面板、状态切换动画；
X11/Wayland 全局钩子监听桌面文件拖拽；
Qt Multimedia 图片 / 视频预览；
Qt 桥接层：C++ 直接链接通用 SDK 静态库，封装调用接口；
通用 SDK 层：与鸿蒙端完全复用同一套底层逻辑；
系统依赖：Linux 窗口置顶权限、文件系统读写、UDP/TCP 网络权限。
4.4 关键技术约束说明
ArkTS 仅用于 HarmonyOS 端 UI 开发，Ubuntu PC 无法运行 ArkTS，统一底层 C++ SDK 实现逻辑复用；
局域网通信完全基于内网 Socket，无 HTTP / 公网接口依赖；
悬浮窗口为系统顶层常驻窗口，需申请对应系统悬浮权限；
中转文件仅本地临时缓存，提供自动过期清理机制，不做永久存储。
4.5 第三方开源依赖
LocalSend：参考其 UDP/TCP 跨设备通信逻辑，自主重构为 C++ 通用 SDK；
SQLite：本地文件与设备数据持久化；
OpenSSL：RSA/AES 加密传输；
Qt6（Ubuntu 端）、ArkUI / 方舟运行时（HarmonyOS 端）。

# 五、构建与运行指南

## 5.1 环境要求

| 端 | 依赖 |
|---|---|
| 共享 SDK（本机构建） | cmake ≥ 3.20、g++（C++17）、OpenSSL、SQLite3 开发头文件 |
| Ubuntu 客户端 | Qt6（Core/Gui/Qml/Quick/QuickControls2/Multimedia）及 QML 模块 |
| HarmonyOS 客户端 | DevEco Studio + HarmonyOS SDK 5.0.0(12)+（工程源码交付，需在该环境构建） |

Ubuntu 依赖安装：
```bash
sudo apt install qt6-base-dev qt6-declarative-dev qt6-multimedia-dev \
  qml6-module-qtquick qml6-module-qtquick-controls qml6-module-qtquick-window \
  qml6-module-qtqml qml6-module-qtqml-workerscript qml6-module-qtquick-layouts \
  qml6-module-qtquick-dialogs qml6-module-qtquick-templates qml6-module-qtquick-shapes
```

## 5.2 构建（SDK + Ubuntu 端 + 测试）

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure   # SDK 单测（含端到端同步测试）
```

产物：
- `build/sdk/liblocalsend-core.a` — 跨端共享静态库
- `build/ubuntu-client/localsend-ubuntu` — Ubuntu 悬浮窗客户端

## 5.3 运行 Ubuntu 客户端

```bash
./build/ubuntu-client/localsend-ubuntu
# 可选参数：
#   --data-dir <路径>   数据目录（默认 ~/.localsend）
#   --tcp-port <端口>   TCP 传输端口（默认 53318）
#   --device-name <名>  设备名称（默认主机名）
#   --local-ip <IP>     本机局域网 IP（默认自动探测）
```

同机双实例联调（错开端口模拟两台设备）：
```bash
./build/ubuntu-client/localsend-ubuntu --data-dir /tmp/a --tcp-port 53320 --device-name 电脑A --local-ip 127.0.0.1 &
./build/ubuntu-client/localsend-ubuntu --data-dir /tmp/b --tcp-port 53321 --device-name 电脑B --local-ip 127.0.0.1 &
```
联调流程：两悬浮窗互相发现 → 一方点「设备管理」发起配对 → 另一方弹窗接受 → 添加文件自动双向同步 → 删除同步删除。

## 5.4 构建 HarmonyOS 客户端

1. 用 DevEco Studio 打开 `harmonyos-client/` 目录（作为工程根）。
2. **放置 SQLite 合并版源码**：OpenHarmony NDK 不提供可链接的 sqlite3 系统库，请从 https://sqlite.org/amalgamation.html 下载 `sqlite3.c` 和 `sqlite3.h`，放入 `entry/src/main/cpp/sqlite/` 目录（CMake 会自动编译；缺失时构建会给出清晰错误提示）。
3. 同步后自动构建 NAPI（`entry/src/main/cpp/CMakeLists.txt` 编译内嵌 `localsend-sdk/` 源码）。
4. 配置签名（DevEco 的 Signing Configs，**无需手动指定 signingConfig**）后运行到真机/模拟器。
5. 权限说明：需 `ohos.permission.SYSTEM_FLOAT_WINDOW`（系统级 ACL 授权，需要应用签名/系统签名支持）以显示悬浮窗；SDK 内 `std::filesystem` 若在目标 SDK 编译失败，请替换为 POSIX 文件 API（详见 `docs/architecture.md`）。
6. 与 Ubuntu 端互通：两端接入同一 Wi-Fi 局域网，鸿蒙端「设备管理」中发现 Ubuntu 设备后互相配对即可双向同步文件。

## 5.5 真机跨设备联调（Ubuntu ↔ HarmonyOS）

1. 两端连接同一 Wi-Fi（同一网段，PRD 不跨网段）。
2. 启动两端客户端，数秒内相互发现。
3. 一端发起配对、另一端确认加入可信白名单。
4. 任一端添加/删除文件，另一端列表实时刷新；传输文件为 AES-128-GCM 加密。
